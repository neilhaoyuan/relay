# Relay

A personal agent development workspace for your own repositories, running on one Linux VM. Assign tasks, follow Codex activity, compare experiments, and review changes. Open the integrated IDE when you need to inspect code or use a terminal.

The first implementation keeps the existing TypeScript server/web workspaces. It replaces the single-terminal prototype with a persistent backend and an integrated CodeMirror editor. Agent spawning is controlled by the owner; there is no Relay MCP server in this version.

## Start locally

Requirements: Node.js 22.16 or newer, npm, Git, and Docker Engine or Docker Desktop using Linux containers. Linux is the deployment target. Native `node-pty` compilation may require Python and C/C++ build tools.

```sh
npm ci
docker build -f infrastructure/Dockerfile.workspace -t relay-workspace:0.1.0 .
cp .env.example .env
npm run dev
```

In PowerShell, use `npm.cmd` and `Copy-Item .env.example .env` if your execution policy blocks npm's PowerShell wrapper.

Open `http://127.0.0.1:8080`; the IDE opens directly. Remote access uses Tailscale Serve as described in [VM_SETUP.md](docs/VM_SETUP.md#access-from-anywhere-with-tailscale). Relay only binds to `127.0.0.1`. Anyone permitted to reach the service through Tailscale has full control of Relay, as do local processes on the host. There is no separate Relay login.

Existing `.relay-data/access-token` files and `RELAY_ACCESS_TOKEN` settings are no longer used. GitHub and Codex authentication still work separately.

You can create workspaces and edit files while Docker is offline. Execution, snapshots, and review/application require Docker so Relay can coordinate container state consistently.

1. Create a workspace with the **+** button beside Workspaces, supplying a Git URL or leaving it empty for a fresh repository.
2. Start its environment, open **Code**, and use **Log into Codex** in the terminal. Complete the device login. The login is shared across environments.
3. Return to **Tasks** and choose **New task**. Select a project, name the task, and describe the work. The default runs in an isolated copy; you can instead choose to edit the primary workspace directly.
4. Select a task to follow its live output, command exit results, and approvals. Search/filter tasks across projects. Closing the browser does not cancel a task.
5. Open **Experiments** for manual experiments or parallel attempts. Select two copies and choose **Compare changes** to inspect their results together.
6. In **Review**, select changed files to see snapshot/result diffs, then **Apply to primary**. This applies the whole reviewed patch; it does not commit or push. If the primary or reviewed copy changed, the backend rejects stale application.
7. Open **Code** at any time for the editor and terminal. Switching views preserves open files and unsaved edits in the current workspace. Switching workspaces still prompts before discarding unsaved changes.

## What is implemented

- Private access through localhost/Tailscale Serve, with host and browser-origin checks on HTTP/WebSockets.
- Git import and persistent primary workspaces; separate source copies for experiments and parallel agents.
- Docker lifecycle and CPU, RAM, PID, and container-count limits.
- Codex app-server adapter pinned to the protocol generated by CLI 0.160.0: threads, resumed conversations, streaming events, approvals, and cancellation.
- SQLite metadata, ordered durable events, queued tasks, and startup reconciliation.
- Default task board with named tasks, status/project filters, approvals, retained activity, and isolated task creation.
- Experiment groups and two-copy comparison; file-by-file side-by-side diffs, binary change notices, patch download, and guarded application.
- VS Code-style interface with a combined workspace/file sidebar, activity rail, compact toolbars, and minimal status chrome.
- CodeMirror editor with draggable, closable tabs, per-file undo history, search, line numbers, conflict-aware saves, and an xterm terminal.
- Resizable sidebar, Codex pane, and terminal; panel visibility controls, left/right Codex docking, terminal maximization, and saved layout preferences.
- Manual experiments, two-task parallel launch UI, FIFO scheduling, retained run history, diff review, and explicit application.
- Parallel worker containers stop after completion to free capacity. Their source files remain until discarded.
- Oracle VM/systemd setup instructions and a file-by-file project map.

## IDE controls

Drag a panel divider to resize it, double-click to reset its size, or focus the divider and use arrow keys. Drag file tabs to reorder them; the close button prompts before discarding unsaved changes. Use the title-bar or activity-rail controls to show/hide panels, the Codex arrow button to change its side, and the terminal square button to maximize/restore it. Layout settings stay in this browser; **Reset layout** restores defaults.

- **Ctrl/Command+Shift+P:** command palette.
- **Ctrl/Command+B:** toggle sidebar.
- **Ctrl/Command+J:** toggle terminal.
- **Ctrl/Command+S:** save the current file.
- **Ctrl/Command+F:** search in the editor.

On small screens, Explorer and Codex open as overlay panels. The editor remains available between them. This is a custom browser IDE; VS Code extensions, arbitrary floating windows, and split editor groups are not implemented.

## Verification

```sh
npm run check
npm test
npm run test:browser
```

`npm test` exercises actual Git and SQLite with a simulated container runtime. `test:browser` builds the app and tests file editing and IDE interactions through an isolated real server. Agent-dependent task, approval, comparison, and review flows use explicit browser API fixtures, without inference calls. It uses installed Edge on Windows; on Linux install Playwright Chromium with `npx playwright install chromium`, or set `RELAY_BROWSER_CHANNEL` to an installed supported channel.

The implementation was checked locally with Docker unavailable. The real Docker image, ARM64 execution, and authenticated Codex tasks still require the VM acceptance run in [VM_SETUP.md](docs/VM_SETUP.md).
