# Relay

A personal development workspace for your own repositories, running on one Linux VM. Browse and edit code, use a container terminal, run Codex, and launch disposable experiments or parallel tasks from your browser.

The first implementation keeps the existing TypeScript server/web workspaces. It replaces the single-terminal prototype with a persistent backend and an integrated CodeMirror editor. Agent spawning is controlled by the owner; there is no Relay MCP server in this version.

## Start locally

Requirements: Node.js 22.16 or newer, npm, Git, and Docker Engine or Docker Desktop using Linux containers. Linux is the deployment target. Native `node-pty` compilation may require Python and C/C++ build tools.

```sh
npm ci
docker build -f infrastructure/Dockerfile.workspace -t relay-workspace:0.1.0 .
cp .env.example .env
npm run dev
```

In PowerShell, use `npm.cmd` and `Copy-Item .env.example .env` if your execution policy blocks npm's PowerShell wrapper.

Open `http://127.0.0.1:8080`. Enter the generated token from `.relay-data/access-token`, or the value you configured as `RELAY_ACCESS_TOKEN`. The token is never printed by Relay.

You can create workspaces and edit files while Docker is offline. Execution, snapshots, and review/application require Docker so Relay can coordinate container state consistently.

1. Create a workspace with a Git URL, or leave the URL empty for a fresh repository.
2. Start the environment. Use **Log into Codex**, then complete the device login shown in the terminal. The login is shared across your environments.
3. Open files in the explorer. Save using the toolbar or Ctrl/Command-S. Use **+** in the explorer to create a file, including nested paths.
4. Submit a task in the Codex panel. Its events and status are saved; closing the browser does not cancel it.
5. With the source agent idle and editor changes saved, create an **Experiment** or launch two **Parallel tasks**. Both parallel agents receive the same source snapshot.
6. After a task finishes, review its changes and explicitly apply them. If the primary workspace changed in the meantime, resolve the differences manually.

## What is implemented

- Private owner login, signed browser sessions, and origin-checked HTTP/WebSocket access.
- Git import and persistent primary workspaces; separate source copies for experiments and parallel agents.
- Docker lifecycle and CPU, RAM, PID, and container-count limits.
- Codex app-server adapter pinned to the protocol generated by CLI 0.160.0: threads, resumed conversations, streaming events, approvals, and cancellation.
- SQLite metadata, ordered durable events, queued tasks, and startup reconciliation.
- CodeMirror file editor with syntax highlighting, tabs, search, line numbers, conflict-aware saves, and an xterm terminal.
- Manual experiments, two-task parallel launch UI, FIFO scheduling, retained run history, diff review, and explicit application.
- Parallel worker containers stop after completion to free capacity. Their source files remain until discarded.
- Oracle VM/systemd setup instructions and a file-by-file project map.

## Verification

```sh
npm run check
npm test
npm run test:browser
```

`npm test` exercises actual Git and SQLite with a simulated container runtime. `test:browser` builds the app and tests it through an isolated server and a real browser, without inference calls. It uses installed Edge on Windows; on Linux install Playwright Chromium with `npx playwright install chromium`, or set `RELAY_BROWSER_CHANNEL` to an installed supported channel.

The implementation was checked locally with Docker unavailable. The real Docker image, ARM64 execution, and authenticated Codex tasks still require the VM acceptance run in [VM_SETUP.md](docs/VM_SETUP.md).
